PDFs are built automatically by the `sc2in/policypress` GitHub Action on every push. No manual steps are required.

## Configuration

The following fields in `config.toml` control PDF output:

```toml
[extra]
organization = "Example Co"    # appears in footers and on the cover page
logo = "logo.png"              # path relative to static/; shown on cover and in headers
pdf_color = "#0e90f3"          # hex color for cover page rule and accents
redact = false                 # default redaction state (overridden by action input)
```

## Draft and redacted builds

The action accepts two inputs that override `config.toml` at build time:

| Input | Effect |
| --- | --- |
| `draft_mode: 'true'` | Adds a DRAFT watermark to every page |
| `redact_mode: 'true'` | Strips content inside `{%/* redact() */%} ... {%/* end */%}` shortcode blocks |

To produce a redacted build for auditors alongside the full internal build, trigger the workflow twice via `workflow_dispatch` - once with `redact_mode: false` and once with `redact_mode: true`.

## Output filenames

PDFs are named from the policy's `title` and most recent `version` in the front matter:

```text
Acceptable_Use_Policy_-_v1.2.pdf
Acceptable_Use_Policy_(Redacted)_-_v1.2.pdf
Acceptable_Use_Policy_(Draft)_-_v1.2.pdf
```

## Accessible (tagged) PDFs — PDF/UA-1

PolicyPress can emit **tagged, accessible PDFs** that conform to
[PDF/UA-1](https://www.pdfa.org/resource/pdfua-in-a-nutshell/) (ISO 14289-1) — the
accessibility standard many procurement and public-sector reviews require. A
tagged PDF carries a structure tree, a document title, and alt text for images,
so screen readers can navigate it.

Enable it in `config.toml`:

```toml
[extra.policypress]
pdf_standard = "ua-1"
```

It is **opt-in on purpose.** PDF/UA-1 is a *hard-fail* standard: if a policy
does not satisfy it, the PDF does not build — it errors. Before turning it on,
make sure every policy meets these rules:

- **Headings must not skip levels.** The PDF title page is heading level 1, so
  a policy body's first heading may be at most `##` (level 2), and you may not
  jump more than one level at a time (`##` → `####` is invalid; add the missing
  `###`). PolicyPress's build pre-flight checks this for you and names the
  offending file *before* Typst runs, because Typst's own error points at an
  internal temporary file that no longer exists by the time you see it.
- **Every image needs alt text.** PolicyPress supplies a generic fallback
  ("Diagram") so mermaid diagrams and other images always pass; add meaningful
  descriptions where you can.

The title page, running header/footer, and the draft watermark are treated as
artifacts and are exempt, so enabling `pdf_standard` does not require changing
how those are authored.

To verify a build is tagged, open the PDF in a reader and check its properties,
or inspect it on the command line — a conformant file reports
`pdfuaid:part 1` in its XMP metadata and contains a `/StructTreeRoot`.

## Technical details

PDFs are generated by [Typst](https://typst.app/). PolicyPress parses the markdown in-process with [zigmark](https://github.com/sc2in/zigmark) and emits Typst markup styled after the classic [Eisvogel](https://github.com/Wandmalfarbe/pandoc-latex-template) template. Mermaid diagrams are rendered to SVG in-process by [pozeiden](https://github.com/sc2in/pozeiden) - no browser or JavaScript runtime is involved, so diagram builds are fast and work on every platform.

## Local PDF generation

To generate PDFs locally without triggering the action:

```sh
nix develop github:sc2in/policypress
policypress -c config.toml -o public
```

For redacted output:

```sh
policypress -c config.toml -o public/redacted --redact
```
