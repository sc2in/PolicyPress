PolicyPress 1.6 is out. The theme this release is *evidence* — giving auditors structured,
verifiable artifacts straight from the build instead of screenshots and copy-paste.

## What's New

### An opt-in machine-readable audit bundle

Turn on `audit_bundle` (flag, config, or action input) and every official build writes an
`audit/` directory beside the PDFs:

- `manifest.json` — one entry per published policy: title, version, review date, owner,
  approver, classification, PDF filename, and the SHA-256 of both the PDF bytes and the
  Markdown source.
- `revisions.json` — every policy's revision history, flattened.
- `coverage.json` / `coverage.csv` — structured SCF and SOC 2 control coverage, using the
  same corrected numerator as the website and report PDFs.

It's deterministically sorted, produced only by official (non-draft) passes, and the
redaction leak check scans it too.

### Compliance reports as real, versioned PDFs

The SCF, SOC 2, and Policy Review reports now render through the same Typst engine, fonts,
branding, and optional PDF/UA-1 tagging as the policy PDFs — replacing the old
print-this-page stopgap. Each build regenerates them under stable names, and the report pages
gained a "Download PDF" button. The Review report carries Current / Due soon / Overdue
statuses driven by `review_overdue_days`.

### A self-service Assurance page

The demo site now publishes its own evidence at `/reports/assurance/`: the live audit bundle,
the binary's CycloneDX SBOM, and the veraPDF PDF/UA-1 and axe-core reports — assembled on
every deploy from the CI gates' own outputs. It's explicitly labelled as verifiable automated
evidence, not a certification.

### TeX math and image alt text in policy PDFs

Set `extra.math = true` on a policy and `$…$` / `$$…$$` now render in the PDF via Typst's
vendored `mitex` package — no network needed at build time — while non-math policies stay
byte-identical. And a Markdown image's alt text (`![description](…)`) now flows into the
tagged PDF, so images meet PDF/UA-1's alt-text requirement with a real description.

### Reports and Guides in the main navigation

Both sections joined the top navigation and now render as card landings instead of the bare
default list.
